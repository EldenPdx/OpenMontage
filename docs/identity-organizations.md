# Organization business API

The authenticated Backlot factory mounts `production/api/organizations.py`. Personal users can create an organization. Select an organization through `/api/auth/workspace` before reading its detail or managing its members. Only its current administrator can invite, cancel an invitation, change a role or remove a member. The roles are the fixed User organization template roles `admin`, `editor` and `viewer`; these endpoints cannot proxy platform Management operations.

Every write carries the session cookie, trusted same-origin `Origin`, `X-CSRF-Token`, `X-Auth-Context` and `Idempotency-Key`. Keep the same key and body when reconciling one operation. A changed identity or workspace requires discarding the pending request. The server checks current authority and target scope before reading accepted results. Foreign or absent targets return 404; an accessible target without the required capability returns 403.

Organization creation records separate create, creator-membership and creator-admin phases. The public 201 is returned only after all three are confirmed. It leaves the selected workspace unchanged. Invitation mail carries a random restricted ticket in the same-origin acceptance URL fragment. Lists, errors and audits exclude the ticket and platform credentials. The accepting identity must have a verified matching email, and a successful ticket is bound to that immutable identity and original operation scope. The UI must remove the fragment from browser history and use `Referrer-Policy: no-referrer`.

Organization writes own a durable per-organization serialization record while their remote outcome is unresolved. Last-admin checks occur within that ownership, and removing or downgrading a member invalidates the affected local authority proof before the remote change and again when committing. External Console administration must coordinate with this control plane to retain the last-admin invariant.

An unknown response returns 503 `outcome_unknown` with `recovery_actions: ["reconcile"]`. Restarting does not release the organization owner or authorize another create, mail send or grant. Reconciliation uses fixed authoritative reads. An organization creation marker identifies its remote organization. Encrypted invitation creation material retains the original ticket, expiry, frozen role and prior invitation IDs before the mail-producing request. Native invitations have no arbitrary application marker; ambiguous or absent matching results remain unresolved. Mail accepted by SMTP before a failed native commit can leave an unusable email, so this process does not promise exactly-once SMTP delivery.

Logto's exact 429 `request.message_rate_limited` records a known mail rejection before sending and rolls back its native invitation transaction. The same actor/workspace/key can continue only after current authority, the fixed template role and absence of a new native invitation are verified. It retains the original encrypted material and organization serialization across restart. Other 429 responses and response loss retain unknown outcomes and cannot authorize another POST. A known rejection that outlives the ticket deadline ends with `invitation_invalid`. These semantics are grounded in the pinned [invitation transaction](https://github.com/logto-io/logto/blob/v1.44.0/packages/core/src/libraries/organization-invitation.ts) and [message guard](https://github.com/logto-io/logto/blob/v1.44.0/packages/core/src/sentinel/message-rate-guard.ts).

Known 401/403/404 and invalid-invitation denials before a remote submission finish their private intent and release organization serialization. They do not resume a rejected operation under another identity. Member target scope and current capability are checked before validating its operation key; an invalid key cannot turn an inaccessible target's 404 into a validation disclosure.

A current administrator may read and confirm an earlier member change's authoritative result when its original actor has left or lost administrator capability. This finishes the original accepted operation and audit; it cannot execute an old actor's unstarted grant. Native acceptance confirmed before the deadline can finish local reconciliation after expiry only with matching native subject, timestamp, organization, membership and frozen role evidence.

Private migration 006 adds encrypted invitation creation material to `organization_intents`. Apply it through the existing migration entry point before enabling this API. Preserve the configured key ring and database binding during backup, restore and key rotation. Removing an older encryption key before its retained operations have been re-encrypted makes those operations fail closed. Never inspect or publish ciphertext envelopes, SDK state or invitation tickets in ordinary production logs.

The fixed adapter bounds authoritative inventory reads at 1,000 entries and fails closed when a complete bounded result cannot be obtained. Administrators of larger installations should extend pagination through the same scoped adapter before enabling them; no global platform count is exposed.

No organization deletion, ownership transfer, billing, SCIM, domain auto-join or account merging endpoint is provided. Real customer SSO, production deployment and paid media calls require their separate workflows.
