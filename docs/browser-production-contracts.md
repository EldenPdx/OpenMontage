# Web Studio v1 contracts

`production/contracts.py` defines the DTOs and ports. The checked-in
`schemas/studio/contracts.schema.json` defines their JSON shapes, and
`schemas/studio/fixtures/` contains fixed module inputs. Pydantic validators and
`check_transition` / `check_approval` supply cross-field/state checks beyond JSON
Schema. Test seams: browser DTO validation, current gate/version/scope matching,
state transitions, managed file references and durable intent semantics.

## HTTP interface

All JSON writes require `Idempotency-Key` (8–128 ASCII letters/digits/_/-), the
same-origin session cookie and `X-CSRF-Token`. The local server validates Host and
Origin; it has no permissive CORS. Non-loopback exposure needs separate authentication.
The browser can select configured profiles but cannot provide an endpoint, credential,
work directory, command or file path. URLs appearing as plain brief text are untrusted
content and never grant permission to fetch or execute them.

| Method | Path under /api/studio | Request | Response |
| --- | --- | --- | --- |
| GET | /config | none | sanitized profiles/capabilities, readiness and CSRF token |
| POST | /tasks | TaskCreate | 202 TaskRecord after durable task + start command commit |
| GET | /tasks | limit 1–100, after task cursor | task list and optional next cursor |
| GET | /tasks/{task_id} | none | 200 TaskRecord |
| GET | /tasks/{task_id}/events | Last-Event-ID or after numeric cursor | persisted SSE stream |
| POST | /tasks/{task_id}/cancel | CancelRequest | 202 current TaskRecord after command commit |
| POST | /tasks/{task_id}/approvals/{gate_id}/decision | ApprovalDecision | 202 current TaskRecord after evidence + command commit |
| POST | /tasks/{task_id}/resume | ResumeRequest | 202 current TaskRecord after resume command commit |

Public task responses contain the approved non-secret profile/model/cost scope and
managed result references, never RunContext, session JSONL, raw Pi messages or
credential headers. The existing board URL is `/p/{project_id}` and final
media uses its existing managed `/media/{project_id}/{relative_path}` route only
after result verification. Creating or opening a page never resumes a task.

Creation example (Idempotency-Key: create_lighthouse_001):

```json
{"brief":"Explain how a lighthouse works","profile_id":"xvan","duration_seconds":30,"aspect_ratio":"16:9","narration":false,"budget_usd_micros":10000000}
```

Idempotency is scoped to operation + resource + key with a canonical request
fingerprint. Same key/same payload returns the committed outcome, even after its
version advanced; same key/different payload is 409 idempotency_conflict. Version
checking happens after successful replay lookup. New writes compare expected_version
atomically; acceptance increments task version and appends durable events in that
transaction. A task ID/run ID/project ID is generated by the backend, never accepted
as an execution location from the client. Identifiers are restricted ASCII slugs.

Errors use `{"error": ErrorDTO}`. 422 invalid_input; 404 not_found; 403 forbidden;
409 version_conflict/idempotency_conflict/state_conflict/approval_conflict/fence_conflict;
503 dependency_unavailable/profile_unavailable; 500 internal_error. Policy failures
include quote_required, budget_exceeded, invalid_artifact, file_conflict and
outcome_unknown and carry only safe, bounded messages and permitted recovery actions.

## Task state and completion

Task states are distinct from checkpoint states (`in_progress`, `awaiting_human`,
`completed`, `failed`). `ALLOWED_TRANSITIONS` is authoritative:

| Current state | Allowed next states |
| --- | --- |
| queued | running, cancel_requested, blocked |
| running | awaiting_approval, blocked, cancel_requested, succeeded, failed, recovery_required |
| awaiting_approval | queued, cancel_requested, recovery_required |
| blocked | queued, cancel_requested, recovery_required |
| cancel_requested | cancelled, failed, recovery_required |
| recovery_required | queued, cancel_requested, failed |
| failed | queued, after explicit validated resume |
| cancelled / succeeded | none |

Same-state updates are allowed only for nonempty whitelisted bookkeeping changes and retain version/fence checks. Duplicate commands do not require another state transition. A failed task is an
execution terminal result but may be explicitly resumed if prerequisites permit it.
Queued transitions on approval/revision/resume release the slot and let the next
command be claimed. Unknown outcome and file/DB contradictions enter recovery_required.

Succeeded requires a canonical completed compose checkpoint and valid render_report
(using the existing artifact schema), an existing nonempty final file under the task
project, and actual ffprobe/media checks (positive duration/dimensions, expected
streams and output format). RenderResult records report/video revision and exact
byte hashes plus verification evidence. Setting a DTO's verified flag is not itself
verification; only trusted worker validation can produce it. Prompt started/queued/
handled, agent_end, agent_settled and tool success never substitute for these checks.

## Approval and revision

A persistent ApprovalRequest includes the displayed artifact/checkpoint references,
summary, allowed option IDs and ApprovalScope. ApprovalBinding fixes task/run/gate,
both revisions and both exact byte SHA256 hashes, plus canonical_sha256(scope).
Scope fixes provider/model, runtime, media models, narration, configuration fingerprint
and budget. Unknown-price consent additionally binds a positive estimated reservation
limit no larger than that budget; it is not a gateway billing hard cap. The backend validates displayed evidence against binding when storing a
gate and re-reads actual file evidence before consuming a decision.

The decision payload must equal that exact binding and current task version. It is
not sufficient to submit only `approve=true`. Backend transactions store durable
human evidence and enqueue exactly one continue/revise/cancel command; the Agent
cannot manufacture evidence, self-report approval, or set trusted human_approved.
Independent model_cost/media_cost gates record backend price/consent evidence
without pretending that evidence is a canonical production checkpoint.
The manifest decides which creative stages require gates; the backend does not invent a
parallel list of creative stages. Pi's temporary extension confirm UI is not a gate.

Approve preserves the displayed chosen scope. selected_option_ids must be a subset
of pending allowed options and the persisted decision/command payload preserves them.
Choosing a provider/model/runtime outside the displayed chosen scope is a revision,
producing fresh artifact/checkpoint revisions, history and a new bound gate before
execution. Revise requires nonempty feedback and supersedes old evidence; append new
decision_log entries with the same category/subject, never erase previous fees or
history. Reject blocks progression; abort requests cancellation. A 409 directs the
browser to fetch the current task/gate before showing new controls.

## Commands, leases, cancellation and recovery

Repository is synchronous; HTTP/async workers call it outside the event-loop thread.
PiRunner and ToolBridge execute asynchronously. Port method signatures live beside
DTOs and implementations depend on these ports rather than each other's internals.
TaskCommand is the durable record for start/continue/revise/cancel/resume and is an
internal DTO, not an arbitrary command API. Claiming is transactional; a claimed
command contains RunContext, current fence and lease owner/expiry.

The first version has one execution slot and one active run per project. assert_fence
checks the live owner/expiry/token before every bridge operation. Heartbeats never
revive an expired fence. A takeover fences old writes and waits for process/OS lock
cleanup; lease timeout alone does not demonstrate that a writer exited.
Recovery retains the expired lease/execution slot until the supervisor verifies the
persisted Pi PID/process-group/start identity and termination. recovery_context
returns the bumped current fence; release_recovered_lease requires that fence and
verified termination. Receipt/file reconciliation may proceed with the current
recovery fence after release, while unknown submissions remain non-retryable.

Cancel acceptance immediately denies new model/tool authorizations. The worker clears
steering/follow-up queue, aborts retries and active work, then closes the full process
group with bounded shutdown. It can accurately report local cancellation while a
submitted remote job may still run and charge. Cancel does not erase reservations,
refund costs, destroy media or pretend to revoke a remote request. Browser disconnect
and SSE disconnect have no cancellation meaning.

Resume first reconciles sessions, canonical checkpoints, all file intents and call
intents. Valid completed stages are not rerun. Known jobs use their stored job ID/
resume reference to query/download with zero new paid POSTs. A submitted request with
no reliable receipt is outcome_unknown, retains its reservation and requires explicit
reconciliation; a generic continue action cannot resubmit it. Reconciliation failure
remains visible. Local file hashes matching neither old nor intended bytes require
human resolution instead of overwrite. This system never claims external exactly-once
execution because a network failure can hide the remote acceptance result.

## Cost and tool boundary

All money is integer USD micros (1 dollar = 1,000,000). Known free cost is 0;
unquoted/unknown cost is null plus price_status, never manufactured zero. Configured
rates are estimates, not the provider's billing authority or a hard remote-spend cap.

Every tool/model operation uses the same journal:
quote/authorize → atomic reservation → durable prepared intent/request fingerprint →
mark submitted before network I/O → durable job/usage receipt → settle once. Retries
and every compaction/summary/nested/warming model request need their own pre-send
policy authorization; requests without interception remain disabled. Unquoted calls
need a specific quote/authorization. Concurrent reservations cannot oversell a quoted
budget. Cancellation and unknown outcomes retain unresolved cost, and existing
cost_snapshot/asset_manifest projections are derived from the same journal.

ToolCall binds task/run/project/fence, a whitelisted registry tool and schema-checked
inputs, optionally current approval binding. Browser/Agent-supplied human_approved,
raw shell, arbitrary HTTP, custom executable scripts/workflows, uncontrolled HTML or
other project paths are rejected. Safe creative authoring is structured through the
existing tools and bounded artifact I/O. Paths are lexical relative references and
must additionally be resolved under their managed root with symlink containment
checks at I/O time. Configuration files, credentials and trusted approval/checkpoint
files are not general writable assets. Registry or cwd is not a security boundary.

## SSE

Each durable event has event_id (monotonic PG sequence), task_id/run_id, task_version,
type, created_at and a sanitized data object. Sequence gaps from transactions or
other tasks are legitimate; filtering never leaks other task data. Commit the event
with its mutation. Replay uses `event_id > cursor`, ordered ascending, in batches of
at most 100 and bounded frames; new subscriptions replay before tailing.

```text
id: 12
event: state
data: {"event_id":12,"task_id":"task-a","run_id":"run-a","task_version":2,"type":"state","data":{"state":"running"},"created_at":"2026-10-09T00:00:00Z"}

: heartbeat

```

The client stores the last applied numeric cursor and fetches current TaskRecord after
refresh/reconnection. If retention removed its cursor, send a `resync` control event
(with latest cursor/current task link) and require refetch; never silently skip retained
business events. Heartbeats and resync controls are not business events and never
change task state. Streams do not hold execution slots or database transactions open.

## Real Pi fixture baseline

Official v1.1.0 source/commit is fixed in the ADR. Transport is stdin/stdout JSONL;
stderr is separate. Frame parsing splits LF/CRLF only, handles split UTF-8 and Unicode
line separators inside JSON strings, correlates command IDs and bounds frame/backlog
sizes. Unknown events are tolerated diagnostically; malformed frames/exit become
safe RPC failures. No shell=True or client-provided command argv.

```json
{"id":"inspect-1","type":"get_state"}
{"id":"prompt-1","type":"prompt","message":"Read AGENT_GUIDE.md and continue the bound task"}
{"id":"prompt-1","type":"response","command":"prompt","success":true,"data":{"disposition":"started"}}
```

Restore by exact session JSONL/ID, never `--continue` (latest session) or `--no-session`.
A handled prompt may have no ensuing agent_settled. Cancel clear_queue before abort;
abort alone permits remaining queued messages to continue. Pi session/internal state
responses are sanitized into business events, never forwarded verbatim to the browser.
A protocol fixture is only a unit-test tool; actual Pi process validation is required.

Default trusted profile: provider xvan, API openai-responses, model gpt-5.6-sol,
backend endpoint https://xvan.ai/v1, credential environment reference NEW_API_KEY.
Another trusted profile can use different provider/protocol/model/endpoint. None are
hardcoded by task/worker logic. Production snapshots also freeze the non-secret
media_configuration_sha256 of trusted media gateway/profile configuration; transport
rejects drift before media HTTP. Deterministic injected test registries may omit this
optional hash. Endpoint and secret values are absent from public DTOs.
Media defaults remain Images2.5-Flare and dreamina-seedance-2-5-260628; narration is
false by default. Live gateway smoke needs separate cost authorization; default CI
uses real Pi/PG with controlled local services and does not invoke paid services.
